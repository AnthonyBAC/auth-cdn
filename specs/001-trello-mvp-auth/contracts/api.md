# API Contract: Trello MVP Auth

## Contract Style

The MVP exposes authenticated HTTP JSON endpoints from the Next.js application. Endpoints must perform session validation, authorization, input validation, and persistence server-side. UI routes may consume these endpoints or equivalent server actions, but the same contract rules apply.

## Common Rules

- All private endpoints require an active session cookie.
- Unauthenticated requests return `401 UNAUTHENTICATED`.
- Authenticated users without the required workspace role return `403 FORBIDDEN` with a clear permission message.
- Resources that do not exist or are not visible to the current user may return `404 NOT_FOUND`.
- Request bodies are JSON unless the endpoint explicitly states otherwise.
- IDs are opaque strings generated by the server.
- Timestamps are ISO 8601 UTC strings generated by the server.
- Role values are exactly `owner`, `editor`, or `viewer`.

## Error Shape

```json
{
  "error": {
    "code": "FORBIDDEN",
    "message": "You do not have permission to update this board.",
    "details": {}
  }
}
```

## Authentication

### Register

`POST /api/auth/register`

Creates a user, starts a session, and automatically creates the user's first personal workspace.

**Request**:

```json
{
  "email": "user@example.com",
  "password": "correct horse battery staple",
  "name": "User Name"
}
```

**Success `201`**:

```json
{
  "user": { "id": "usr_123", "email": "user@example.com", "name": "User Name" },
  "workspaceId": "wks_123"
}
```

### Login

`POST /api/auth/login`

**Request**:

```json
{
  "email": "user@example.com",
  "password": "correct horse battery staple"
}
```

**Success `200`**:

```json
{
  "user": { "id": "usr_123", "email": "user@example.com", "name": "User Name" }
}
```

### Logout

`POST /api/auth/logout`

Revokes the current session and clears the browser session cookie.

**Success `204`**: empty body.

### Current Session

`GET /api/auth/session`

**Success `200`**:

```json
{
  "user": { "id": "usr_123", "email": "user@example.com", "name": "User Name" }
}
```

## Workspaces

### List Workspaces

`GET /api/workspaces`

Returns workspaces where the current user has active membership.

**Allowed Roles**: owner, editor, viewer

**Success `200`**:

```json
{
  "workspaces": [
    {
      "id": "wks_123",
      "name": "Product Team",
      "role": "owner",
      "locationName": "Paris, France"
    }
  ]
}
```

### Create Workspace

`POST /api/workspaces`

Creates a workspace and makes the current user owner.

**Request**:

```json
{
  "name": "Product Team"
}
```

**Success `201`**:

```json
{
  "workspace": { "id": "wks_123", "name": "Product Team", "role": "owner" }
}
```

### Get Workspace

`GET /api/workspaces/{workspaceId}`

**Allowed Roles**: owner, editor, viewer

### Update Workspace Location

`PATCH /api/workspaces/{workspaceId}/location`

**Allowed Roles**: owner

**Request**:

```json
{
  "locationName": "Paris, France",
  "latitude": 48.8566,
  "longitude": 2.3522,
  "timezone": "Europe/Paris"
}
```

**Success `200`**:

```json
{
  "workspace": {
    "id": "wks_123",
    "locationName": "Paris, France",
    "latitude": 48.8566,
    "longitude": 2.3522,
    "timezone": "Europe/Paris"
  }
}
```

## Memberships and Invitations

### List Members

`GET /api/workspaces/{workspaceId}/members`

**Allowed Roles**: owner, editor, viewer

### Invite Member

`POST /api/workspaces/{workspaceId}/invitations`

**Allowed Roles**: owner

**Request**:

```json
{
  "email": "collaborator@example.com",
  "role": "editor"
}
```

**Success `201`**:

```json
{
  "invitation": {
    "id": "inv_123",
    "email": "collaborator@example.com",
    "role": "editor",
    "expiresAt": "2026-09-06T12:00:00Z"
  }
}
```

### Accept Invitation

`POST /api/invitations/{token}/accept`

Creates or activates membership for the authenticated invitee.

### Change Member Role

`PATCH /api/workspaces/{workspaceId}/members/{userId}`

**Allowed Roles**: owner

**Request**:

```json
{
  "role": "viewer"
}
```

### Remove Member

`DELETE /api/workspaces/{workspaceId}/members/{userId}`

**Allowed Roles**: owner

Must reject removal of the last owner.

## Time and Weather Context

### Get Workspace Context

`GET /api/workspaces/{workspaceId}/context`

**Allowed Roles**: owner, editor, viewer

Returns current or cached context for the workspace location. Failures must return a non-blocking unavailable status.

**Success `200`**:

```json
{
  "context": {
    "status": "available",
    "locationName": "Paris, France",
    "timezone": "Europe/Paris",
    "localTime": "2026-08-30T14:00:00+02:00",
    "weatherSummary": "Partly cloudy",
    "temperature": 23.4,
    "observedAt": "2026-08-30T12:00:00Z"
  }
}
```

**Provider Failure `200`**:

```json
{
  "context": {
    "status": "unavailable",
    "message": "Time and weather context is unavailable. Boards remain usable."
  }
}
```

## Validation Limits

| Field | Rule |
|-------|------|
| Workspace name | 1-100 trimmed characters |
| Board title | 1-100 trimmed characters |
| List title | 1-100 trimmed characters |
| Card title | 1-200 trimmed characters |
| Card description | 0-10,000 characters |
| Latitude | -90 to 90 |
| Longitude | -180 to 180 |
| Role | `owner`, `editor`, or `viewer` |
| Timezone | Valid IANA timezone |

## Required End-to-End Contract Scenarios

- Registering creates a signed-in user and an owned personal workspace automatically.
- Signed-out users cannot retrieve private workspace or board data.
- Owners can invite collaborators, change roles, and update workspace location.
- Editors and viewers cannot update workspace location.
- Editors can manage boards, lists, and cards but cannot manage membership or workspace deletion.
- Viewers can read boards, lists, and cards but cannot mutate them.
- Board/list/card changes persist after sign-out and sign-in.
- Time/weather provider failure returns unavailable context without breaking board endpoints.
